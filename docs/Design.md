# Design

## 문서 목적

이 문서는 시각적 원칙, 화면 해석 기준, UX Writing 기준을 함께 정리한다.

## 시각 원칙

- 상태 정보는 화면 상단에서 우선 노출한다.
- 섹션은 명확한 위계와 간격으로 분리한다.
- 반복 콘텐츠는 패턴 단위로 일관되게 구성한다.

## 레이아웃 원칙

- 임의 마진보다 `Stack`, `PageSection`, token 기반 간격을 사용한다.
- 화면 좌우 여백은 `ScreenContainer` 기준을 우선한다.
- 화면 수준 구조는 `patterns` 우선, 세부 배치는 layout primitive로 해결한다.

## 타이포그래피 원칙

- token으로 정의된 semantic typography를 우선 사용한다.
- 상태/라벨/본문/보조 정보의 위계를 혼합하지 않는다.

## 상태 표현 원칙

- 진행 상태는 맥락에 맞는 ProgressBar를 사용한다.
- 배너/카드/리스트의 tone과 상태 표시는 분리해서 해석한다.
- `ERROR`, `EMPTY`, `COMPLETE`는 메인 화면과 구분되는 상태 화면으로 해석한다.

## 접근성 원칙

- 텍스트와 배경의 대비는 WCAG AA 기준을 우선 확인한다.
- 상호작용 컴포넌트의 경계선, 아이콘, 포커스 링은 비텍스트 UI 기준으로 확인한다.
- disabled, subtle, status color는 시각 의미와 접근성 기준을 함께 검토한다.

## WCAG AA 체크리스트

- 일반 텍스트가 배경 대비 `4.5:1` 이상인가
- 큰 텍스트가 배경 대비 `3:1` 이상인가
- 입력창, 칩, 체크박스, 라디오, 탭, 프로그레스 등 비텍스트 UI 경계가 `3:1` 이상인가
- 포커스 링이 주변 배경과 충분히 구분되는가
- 상태 색상(`error`, `success`, `warning`, `information`)이 단독으로도 읽히는가
- `disabled`와 `subtle`이 의미상 구분되면서도 필요한 경우 충분히 보이는가

## UX Writing 원칙

ATCHA의 문구는 정보를 전달하는 것에 그치지 않고, 사용자의 불안과 판단 부담을 줄여야 한다.

- 현재 상태가 무엇인지 설명한다.
- 사용자가 다음에 해야 할 행동을 바로 이해할 수 있게 안내한다.
- 긴급도와 해결 가능성을 함께 전달해 과도한 불안을 줄인다.

## UX Writing 구조

문구는 가능한 경우 아래 순서를 따른다.

1. Explain: 현재 상태와 의미를 설명한다.
2. Guide: 사용자가 지금 할 행동을 구체적으로 안내한다.
3. Reduce: 긴급도와 불안을 조절하는 문장을 덧붙인다.

## UX Writing 작성 규칙

- 상태만 던지지 말고 이유나 영향을 함께 설명한다.
- 추상적인 권유보다 바로 행동 가능한 안내를 사용한다.
- 어려운 정비 용어는 생활 언어로 풀어쓴다.
- 공포를 유도하는 표현보다 해결 가능성을 함께 전달한다.
- 짧고 명확하게 쓴다.

## 금지 표현

- 상태 없는 문장
  - 예: `문제가 발생했습니다`
- 행동 없는 문장
  - 예: `점검 필요`
- 공포 기반 표현
  - 예: `지금 안 하면 위험합니다`
- 강압적 표현
  - 예: `지금 교체하세요`

## 문구 QA 체크리스트

- 사용자가 현재 상황을 이해할 수 있는가
- 사용자가 바로 행동할 수 있는가
- 사용자의 불안이 줄어드는가
